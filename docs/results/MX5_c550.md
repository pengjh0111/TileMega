## Stage B contract requiring clarification

Spec file locations: `/root/Prompt/TileMega_MX5_prompt.md:270` (fixed
`Body::Prefetched` return type), `:272` (`kLoads` constexpr), `:284`
(geometry/resource-dependent P_w), `:403` (six-coordinate instance sharing),
`:421` (runtime bench N/K/B and six GEMM template coordinates).

The formula admits different P_w for the same six coordinates. A CPU
reproduction is in `test/unit/mx/decode_geometry_v2.cpp:67`: Llama-3.2-1B O
(N=2048,K=2048) and down (N=2048,K=8192), B1, TN16/WN1/D1, residual, no norm,
TileRange, G104. Conditional on R_next=156, the prescribed widths are 8/16,
and their per-lane weight load counts are 8/16. **156 is a permitted example,
not a measured v2 resource value.** Coverage, owner and contributor-count
properties of both partition types passed on CPU (verified).

A single fixed `Body::Prefetched::kLoads` cannot express both widths under
the literal shared-instance contract. A concrete proposed amendment is to
include derived P_w in implementation specialization/instance sharing, retain
the six searched coordinates, and dispatch the same specializations in the
runtime-shape bench. This amendment is not implemented. Per spec §0.2, the
prefetch-chain item is stopped pending the user's clarification; later
dependent LLM/DNN stages have not been started.
