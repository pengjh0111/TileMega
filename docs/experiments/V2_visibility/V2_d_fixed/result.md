# V2-d′：修掉 §0.5 的两个 bug 之后

## 结论

✅ **两个 bug 都与缺陷无关。单独修、一起修，失败率都不变（50/50）。**
它们仍然是应该修的规范违反，但对本缺陷的贡献是 **0**。

## 两个 bug

1. **`token=%chain` 应为 `token=%tk`** —— flag release 的 `for` 循环声明了循环携带
   token `%tk`，但每次迭代都传 `token=%chain`，导致循环携带 token 是死值，
   各次 release 之间没有串起来。
2. **数据 store 的 `weak` 应为 `relaxed device`** —— 规范 §7.2 禁止用 `weak`
   做线程间通信，编译器可以假设不存在并发访问。

```
  v2_d_tokfix    50/50                     v2_d_tokfix    50/50
  v2_d_weakfix   50/50                     v2_d_weakfix   50/50
  v2_d_both      50/50                     v2_d_both      50/50
```

✅ **已验证：归因 = 两个 bug 各贡献 0%。**

## 错值结构（对 warp-partial 模型的独立佐证）

V1-d 的消费者在一个 64 次的循环里归约 64 个 chunk，期望 65536。抽样错值：

```
65536 - 58112 =  7424 = 29 x 256
65536 - 54528 = 11008 = 43 x 256
65536 - 46336 = 19200 = 75 x 256
65536 - 58368 =  7168 = 28 x 256
65536 - 53760 = 11776 = 46 x 256
65536 - 52736 = 12800 = 50 x 256
65536 - 53504 = 12032 = 47 x 256
65536 - 51968 = 13568 = 53 x 256
```

✅ **每一个亏损都是 256 的整数倍**，256 = 32 lane × 8 元素 = 一个 warp partial。
这是在一个与 V1_min 结构完全不同的 kernel 上得到的独立确认。
