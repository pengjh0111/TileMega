# Part 1 — semantic operator recovery, normalization invariance, degradation

Reproduce with `docs/experiments/SEMANTIC/run.sh` (CPU only; needs
`.venv/site` torch 2.13.0+cpu and `build-portable`). Raw output in `raw/`;
the two large FX node dumps per model are regenerated by the script rather
than committed.

## 1(a) Normalization through torch's own decomposition

`ExportedProgram.run_decompositions()` is called by `export_bridge.py
--decompose`; no lowering rule is written by hand. Node counts and the
operator vocabulary before/after (`raw/*_core_report.json`):

| model | call_function nodes | distinct targets |
|---|---|---|
| 2-layer GQA | 179 → **247** | 30 → **28** |
| 4-layer MHA | 355 → **487** | 30 → **28** |

Targets that disappear: `linear`, `matmul`, `softmax.int`, `silu`, `chunk`,
`masked_fill.Scalar`, `contiguous`, `to.dtype`, `transpose.int`, `outer`,
`repeat_interleave.self_int`, `arange.default`, `arange.start`.
Targets that appear: `mm`, `bmm`, `_softmax`, `sigmoid`,
`split_with_sizes`, `where.self`, `permute`, `expand`, `clone`,
`scalar_tensor`, `arange.start_step`.

✅ verified — the frontend produces the **byte-identical generated CUDA** from
both forms, on both models (`raw/normalization.txt`: `STAGES_IDENTICAL` and
`CODEGEN_IDENTICAL` for `e2e` and `mha`), and that file is in turn identical
to the committed `E2E_GEN/raw/generated_e2e.cu` and
`P3_GENERALIZATION/raw/generated.cu`. The plan is recovered from use-def
structure, so normalization moves 68 (resp. 132) nodes without moving a
single stage.

⚠️ One thing normalization does destroy: `ExportedProgram._guards_code` is
empty after `run_decompositions()` (4 → 0 guards on GQA, 11 → 0 on MHA;
`range_constraints` survive). That is torch's behaviour, not the bridge's —
checked directly on the loaded program. Today it costs nothing downstream
(the generated file is unchanged, since the guards only feed
`tilemega.guard_count` and the symbol-alias dictionary), but a pass that
needs `s61 == s14` must run on the pre-decomposition program or re-derive it.

## 1(c) Grouping by use-def structure, not by name

`lib/Frontend/ModelPlan.cpp` no longer contains a single ATen target literal
or parameter-name literal. What was removed:

| removed | count | what it assumed |
|---|---|---|
| `std::regex "^layers\.([0-9]+)\.(.+)$"` | 1 | layer index encoded in the parameter FQN |
| `Require(layer, "<module>.weight")` | 10 | `q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, `down_proj`, `input_norm`, `post_norm`, `inv_freq` |
| `"past_k" + N` / `"past_v" + N` | 2 | KV inputs named by convention |
| `input.name.find("past_") != 0` | 1 | the hidden input is the one *not* called `past_*` |
| target literals in `Linear`/`Consumer`/`CacheConcat`/`FirstAttention`/`SecondAttention` | 6 | the composite spelling of the op (`aten.linear`, `aten.matmul`, `aten.cat`) |
| `head_dim = numel(inv_freq) * 2` | 1 | RoPE table layout |

**21 name- or target-dependent decisions removed.** What replaces them is one
declarative pattern of 17 slots (`DecoderLayerPattern()`), stated as operand
values, dependence, and two axis constraints.

What remains, and why:

* `CoreRoles()` — 13 semantic roles over 30 ATen targets, in
  `lib/Frontend/GraphPattern.cpp`. This is the one place a target string is
  compared, and it is what makes the composite and Core ATen spellings the
  same role. It is a vocabulary, not a branch: adding an operator adds a row.
* `LayoutOnly()` — 12 targets that re-index without changing a value.
  Required because normalization inserts `view`/`permute`/`expand` chains
  between every pair of real operators.
* `known()`/`classify()` in `lib/Frontend/Frontend.cpp` — the task-kind
  classification for the CG. Uncovered targets fall through to `generic`.

Two structural constraints were needed and are worth naming:

* `Near(role, slot)` — plain dependence is transitive and therefore blind to
  layer boundaries: every projection of layer L is a predecessor of every
  attention of layer L+1, so `Dep` alone matched 10 bindings on a 2-layer
  model. `Near` asks for the *nearest* node of a role behind an operand.
* The KV concats are pinned by `Input()` — each cache appends to a model
  input, which is what separates them from RoPE's rotate-half concat without
  naming either.

## 1(d) Degradation, not refusal

`test/fixtures/export_unsupported.json` is a 2-operator graph whose second
operator (`aten.imaginary.default`) no rule covers. `frontend_degradation`
(ctest) asserts the import **succeeds**: `raw/degradation.txt` reports
`DEGRADED ops=1 task_spaces=2 generic=1`, no `tilemega.model_plan`, and one
task space per operator. The importer prints `IMPORT_DEGRADED` on stderr and
records the targets in `ImportSummary::degraded`.

This is a deliberate behaviour change: the old frontend threw
`operators outside Phase-1 whitelist`, and `frontend_import_test` asserted
that rejection. The assertion was rewritten to assert degradation, per
skeleton §0.1 ("能降级就不要报错"). Codegen still refuses a degraded module —
`verified CG has no tilemega.model_plan` — which is the honest boundary: the
graph imports and can be analysed, but there is no megakernel plan for it.

### End-to-end on hardware

Both models, both normalization forms, compiled from the matcher's own output
in `raw/` and run on the RTX 4090 (`raw/hw/hardware.txt`, reproduce with the
commands in `run.sh`'s trailing comment):

| binary | `l05_ms` | `l1_ms` | `l2_ms` | L1 vs L0.5 | L2 vs L1 | L2 iter1 vs iter0 | output hash | result |
|---|---|---|---|---|---|---|---|---|
| `e2e_plain` | 1.113088 | 1.083392 | 1.119232 | 0 mismatches | 0 mismatches | 0 mismatches | `5245714bc5d3ab4d` | PASS |
| `e2e_core` | 1.105920 | 1.082528 | 1.117184 | 0 mismatches | 0 mismatches | 0 mismatches | `5245714bc5d3ab4d` | PASS |
| `mha_plain` | 2.197664 | 2.159616 | 2.229312 | 0 mismatches | 0 mismatches | 0 mismatches | `fd15fa2e89cdb915` | PASS |
| `mha_core` | 2.189312 | 2.158784 | 2.228384 | 0 mismatches | 0 mismatches | 0 mismatches | `fd15fa2e89cdb915` | PASS |

All three levels agree bitwise (`max_abs=0` on both comparisons), and so do the
two normalization forms — as they must, since the generated `.cu` is
byte-identical between them. The only nonzero difference anywhere is
`l05_vs_l0`, the megakernel against the host reference: `max_abs=1.55e-06`
(gqa2) and `1.91e-06` (mha4), which is f32 accumulation-order noise, not a
level difference. The hashes are the same values the committed E2E artifacts
record, so the declarative matcher reproduces the hand-written path exactly on
the device and not merely in the generated text.
