# V2-e：事件与数据**都**分布式

## 结论（先行）

❌ **真实 megakernel 的形态并不安全。** 事件完全分布式（每个 flag 一写一读、128B 对齐）
且数据完全独占（每个 chunk 一写一读）的任务图链条，**仍然稳定复现同一个缺陷**，
grid=8 就已经出错。

这是用户在任务书里预期的"极有价值的负面信息"。

## 两个版本，以及为什么第一个版本的"全过"是假象

### v2_e：先生产、后消费 —— 300/300 全过，但这个结果**不可采信**

```
grid    failed/50
8       0/50
30      0/50
80      0/50
120     0/50
170     0/50
340     0/50
```

我一开始把这读成"分布式事件+独占数据是安全的"。**这是错的。**

`v2_e` 里每个 block 先写 1024 个 float（生产 chunk bx+1、release flag[(bx+1)*32]），
**然后**才去自旋等待自己的 flag[bx*32]。而它等的那个 flag 由 block bx-1 释放——
bx-1 是更早调度的 block，等 block bx 干完自己那一整块 store 走到自旋点时，
上游的 flag 早就是 1 了。于是**剥离出来的第一次 poll 就命中，所有 warp 在同一轮退出，
根本没有人真的自旋过**。

这与 `V2_NO_SYNC`（host 预置 flag、无人自旋）0/50 全过是同一件事。
`v2_e` 测的不是"分布式事件安不安全"，而是"没有真自旋时安不安全"。

### v2_e2：先消费、后生产 —— 真实任务图，全线失败

把两个角色调换，链条变成严格串行：block bx 必须先消费完 chunk bx 才能 release
flag[(bx+1)*32]，因此 block bx+1 **必然**处在自旋中等待翻转。这才是真实的任务图形态。

```
grid    failed/50   bad-value histogram
8       11/50       512 x11
30      25/50       256 x3   512 x20  768 x11
80      50/50       256 x12  512 x50  768 x4
120     50/50       256 x17  512 x50
170     50/50       256 x20  512 x50  768 x9
340     50/50       256 x50  512 x50  768 x43
```

✅ **已验证。** 正确答案是 1024；出现的错值 768 / 512 / 256 分别对应丢失 1 / 2 / 3 个
**warp partial**（每个 partial = 32 lane × 8 元素 = 256），与 SUMMARY.md 里的机理完全一致。

## 2×2 析因：到底哪个变量是分类变量？

§0.4(1) 提出"分类变量是**数据是否共享**，不是事件是否分布"。为了检验，做了
flag{shared, dist} × data{shared chunk, 独占 chunk} 的 2×2。

**第一次尝试（`gen_2x2.py`，v2_x_*）四格全过 0/50——但和 v2_e 是同一个坑**：
每个 block 都先写一块数据再自旋，没人真的等过。这批数据作废，仅作为方法论记录保留。

**第二次（`gen_2x2b.py`，v2_y_*）改成 V1_min 形态**：block 0 是纯生产者（循环写满
grid 个 chunk，很慢），block bx≥1 是纯消费者、**立刻**开始自旋。grid=340，每格 50 次全新进程：

| | data = 独占 chunk bx | data = 共享 chunk 0 |
|---|---|---|
| **flag = 共享 flag[0]** | **50/50 失败** | **50/50 失败** |
| **flag = 分布 flag[bx*32]** | **50/50 失败** | **50/50 失败** |

✅ **已验证：四格全失败。事件是否分布、数据是否共享，两个维度都不是分类变量。**

## 对 §0.4(1) 的裁决，以及 V1 结论为什么会错

§0.4(1) 说得对的部分：**V1-d 确实没有测到它声称要测的东西**，V1"每 tile 事件张量也躲不掉"
的结论确实下早了。

§0.4(1) 说错的部分：**分类变量也不是"数据是否共享"。** 上表右下 vs 左下已经直接证伪。

V1 之所以会得出"数据共享是分类变量"，是因为 **V1-a 与 V1-b 一次变了两个量**：

| | 数据 | `reduce` |
|---|---|---|
| V1-a（通过） | 独占 chunk | **没有 reduce**（`grep -c reduce v1_a.mlir` = 0，SASS 里 `STS=1 LDS=0`，无 warp 间归约级） |
| V1-b（失败） | 共享 chunk 0 | 有 reduce |

V1-a 的消费者把 `tile<1024xf32>` 乘 2 后整块存回去，**从头到尾没有跨 warp 归约**。
把 reduce 固定住、只改数据共享性（上面的 2×2），四格全败；
把数据独占性固定住、只增删 reduce（V1-a 通过 vs `v2_y_shared_excl` 失败），
结果直接翻转。**真正的开关是 `reduce` 带来的共享内存跨 warp 级，不是数据共享。**
