## F5 discrepancy and required decision

stated by the prompt: independent stage search lacks shared-memory filtering
and infeasible choices surface at nvcc `static_assert`.

verified by source inspection: independent search and missing filtering are
accurate, but the failure-stage clause is not:

| location | actual behavior |
| --- | --- |
| [Sm90ForwardPlan.cpp](../../lib/Solver/Sm90ForwardPlan.cpp#L205) | computes residency budget and arena, without candidate feasibility checks |
| [ForwardCodegen.cpp](../../lib/Codegen/ForwardCodegen.cpp#L800) | stages larger than `1024+arena` use offset zero |
| [Sm90ForwardProgram.cuh](../../include/tilemega/Codegen/tasks/Sm90ForwardProgram.cuh#L281) | `Placed` permits exclusive placement; no total shared-memory budget assertion |
| [Sm90ForwardRuntime.cuh](../../include/tilemega/Codegen/tasks/Sm90ForwardRuntime.cuh#L112) | `tm_plan_create` calls `cudaFuncSetAttribute` and occupancy API; insufficient residency throws `native forward plan exceeds its measured residency` |

No failing resource configuration was executed. The verified claim describes
the source's validation mechanism, not an observed GPU failure.
Proposed factual correction: “search does not filter candidate resources;
materialization computes the arena and codegen permits exclusive placement;
CUDA plan creation checks shared-memory support and actual residency.”
Resuming requires user direction under §0.3; S3's planned resource filtering
remains applicable.
