## Execution and comparison

- **verified** nine immutable main references resolved by binary SHA, original
  selected CU, prefill binary, retained tokens and selection/timing evidence.
  No AB4b measurement jobs exist. Production paths/pins/results are unchanged.
- **verified** both new arms retain each selected body and shape. One kernel
  runs each existing MetaX stage; cross-stage prefetch is removed. A MoE
  gate_up kernel materializes the per-CTA LDS RouteTable for the down kernel.
  Existing internal stage reductions remain part of their bodies.
- **inferred** this measures execution-boundary and lost-locality costs
  relative to the current main implementation. It does not isolate launch
  overhead from those costs. The historical main reference is not a new
  contemporaneous P-PAIR or SM90's independently searched AB4b reference.
- **verified** Graph uses one captured decode step plus a device cursor;
  host-launch enqueues the same kernels without Graph. Both reuse main prefill.
- **stated** protocol inherited from SM90R6: each arm has five fresh correctness
  processes and three fresh timing processes; timing has warm1 + timed3 for
  N1024 and N1. R6 TPOT is `(median(E2E_N1024)-median(E2E_N1))/1023`.
  MetaX event-TTFT TPOT is retained separately for the compatible main ratio;
  the two definitions are not silently interchanged.
- **verified** initial Graph functional probe: **5/5 fresh processes**, each
  2000 replays of three kernels, zero mismatches. This is a functional probe,
  not qualification of all model plans.
- **verified** Qwen3-1.7B B1 and OLMoE B1 initial Graph smoke runs match
  single-step/loop over 1024 generated tokens and their frozen main reference
  over the available length. Full arm qualification is tracked separately.
- **verified** OLMoE B16 Graph full qualification has **5/5 fresh processes**
  with 1024-token single-step/loop and inter-process equality. HF teacher forcing
  covers 256 positions per row and passes. Other arms remain in the queue.
- **stated** frozen main token evidence may contain 512 or 1024 tokens;
  `main_reference_tokens` records the actual length. The new single-step/loop,
  inter-process and cross-arm comparisons always cover 1024 tokens.

## Bandwidth definition and inputs

- **verified** inventory: 220 frozen timing rows = 30 dense TP1 scopes,
  10 MoE TP1 scopes, and 15 Qwen3-1.7B TP2/TP4/TP8 scopes, four systems each.
  Latest TP8 final rows supersede earlier TP8 rows; original files are untouched.
- **inferred** logical payload counts BF16 attention/MLP/router/head weights,
  distinct active MoE expert weights, and average KV reads at L=576.
  It excludes activation/intermediate writes, padding, redundant reads, norms
  and communication. TP uses per-rank payload. Efficiency is payload divided
  by frozen TPOT and the measured single-card HBM peak; it is not a DRAM counter
  or a communication-inclusive hardware-bound score.
- **stated** hardware sampling: 8 GiB vector/LDS read and BF16 MMA items;
  five fresh processes per item on each authorized card. Normalize with the
  largest valid configuration median after all hardware sampling finishes.
- **verified** C550 64 KiB LDS supports the 32 KiB x2 ring. The source design's
  x4/x8 rings would need 128/256 KiB and are recorded unsupported.
- **stated** B1 active experts are exactly top-k=8. B>1 uses eight new
  1024-position reference captures: past63 from prompt and past64..1086 from
  decode. One common trajectory prices all four engines. Older 64-step
  captures are not presented as 1024-position observations.
- **verified** two initial captures have completed: OLMoE B2 mean distinct
  experts 15.18682861328125; B16 55.1009521484375 over 1024 positions and all
  16 layers. Both match the retained main generated-token prefix. These are
  new trajectory statistics, not replacements of MX6's older 64-step rows.
