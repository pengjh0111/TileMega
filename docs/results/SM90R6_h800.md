# SM90R6 H800 experiment checkpoint

This is an incomplete R6 checkpoint, not CP-P or the final ablation report.
The governing instructions are `TileMega_SM90R6_prompt.md` and the recovered
`TileMega_SM90R6_continue1` instructions under `runs/sm90r6/sync/`.
DNN work is being collected separately in `/root/TileMega-dnn1`.

## Hardware measurements

Verified: `SM90R6_hw_peaks.csv` contains 56 supported configurations across
GPU 0–5 and 7, each with five accepted fresh processes. The maximum
configuration medians are 3235.332 GB/s HBM reads and 988.728 TFLOPS BF16
WGMMA. These are measured diagnostic peaks, not application performance.
`scripts/sm90r6_merge_peaks.py` checks the summary against all 140 selected
raw processes, including sample counts, extrema, medians and guard results.
Raw evidence: `runs/sm90r6/h1/protocol_v2/validated_manifest.json`.

Verified limitation: eight 32 KiB bulk slots require 262208 bytes including
barriers, exceeding the reported 232448-byte CTA limit. The user approved
recording this configuration as unsupported. Four slots also prevent two
such CTAs from residing simultaneously in one SM; the two-CTA-per-SM grid
is a launch-size configuration, not proof of that residency. Details are in
`SM90R6_hw_support.csv`.

The original process ranges are retained. For example, GPU0 bulk x4 with
one CTA per SM has a 7.45% range; no sample was removed to narrow it.
Clocks were observed, not changed. Parallel collection used the user's
explicit trial authorization. DT-P remains unverified. The guard records
provisional acceptance because host PID ownership is not fully visible
inside the container; physical-card locks and per-run telemetry remain in
the raw evidence. These qualifications also apply to derived normalization.

## MoE routing and lower bounds

Stated user decision (2026-11-04): predictive MoE task domains use the
nearest integer to each expected active-expert tile task count. The finite
CTG domain and its dependencies must carry an approximation label. This
convention does not replace or round the observed H2 routing measurements;
the resulting predictions remain approximate.

ownership projections are implemented. CPU tests check 40 task counts
against independent decimal evaluations and 160 gate-up/down geometry
pairs, including the truncated final expert slot and per-column combine
releases. Task prices and domain JSON explicitly label this approximation.
Evidence: `runs/sm90r6/moe-domain/tests4.log`.

Verified: all four frozen MoE cells now build complete predictive graphs
with per-CTA local route tasks, finite expert dependencies, per-column
combine tasks and the corrected residual def-use to the next layer/head.
CPU integration checks cover counts, counted/local releases, isolated sums,
cache reuse and template replay. Local-route pricing still uses the older
RouteLa-minus-barrier constant as an explicitly labeled proxy; no constant
was fitted. The projected graph is not claimed to be fully represented in
the executable MLIR module. Evidence: `runs/sm90r6/moe-ctg/frozen-v2/`;
dense CTG regression passed in 131.71 seconds.

Verified: `SM90R6_moe_routing.csv` has 320 layer rows covering both MoE
models at B1/2/4/8/16, each over 1024 generated positions. Qwen uses
`qwen_isl64.json`; OLMoE uses `olmo_isl64.json`. Earlier OLMoE captures
using the Qwen prompt are excluded. OLMoE B1's corrected prompt and routing
trace passed five fresh processes with identical tokens and route indices.
The B4 prompt-path memcheck completed with zero errors.

Raw evidence: `runs/sm90r6/h2/olmo-frozen-prompts-v4` and the five individual
Qwen cell roots under `runs/sm90r6/h2/full_v3`. The merger rejects missing
positions, invalid experts, mixed model/prompt identities and failed guards.

Inferred from these measurements and the frozen timing sources:
`SM90R6_hw_bound.csv` contains 281 LLM cells, each with measured-peak and
nominal-peak bases (562 rows). It preserves the R16 dense logical-byte
definition, uses H2's measured distinct experts for MoE bytes, and includes
the prescribed TP communication floor. Every row identifies and hashes its
timing, model, peak, routing and target inputs. All measured-basis ratios
are below one; the largest is 0.853927 for TileMega Llama-3.1-8B B16 TP1.
This is a logical-byte lower-bound calculation, not measured DRAM traffic.
DNN rows and future R6 ablation winners are not included yet.

## Engine kernel boundaries

Verified: `SM90R6_kernel_boundary.csv` has all 12 engine/model/batch cells;
`SM90R6_kernel_boundary_gemm.csv` has 60 GEMM-family rows. Both now use the
complete H1 bandwidth above. Raw reports are under
`runs/sm90r6/i1/protocol_v2`. The preexisting edited boundary CSV was
preserved at `runs/sm90r6/sync/kernel-boundary-before-final.csv` before
replacement by the complete validated matrix.

Worker hooks bracket 64 actual decode forwards after step 256. Analysis
identifies a repeated kernel sequence, validates auxiliary stream periods,
and measures the middle 32 steps. Busy time uses the union of kernel
intervals; split-K reductions join their GEMM on the same CUDA stream.
All accepted captures have successful guard and child exits. Failed MPI
startup and TRT destructor attempts remain in the raw tree and are excluded.

The capture-window TPOT and the full-run TPOT are both compared with the
frozen TPOT. The former also differs in KV length from the full-run average,
so its difference must not be interpreted as pure profiler overhead. GEMM
rates and hardware floors use logical bytes and are labeled as inferred.
