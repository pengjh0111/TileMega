# V2-g：把"grid 大小"与"并发读者数"分开

grid **固定为 340**，只改参与握手的消费者数量 K（bx ≤ K 的 block 参与，其余直接退出）。
每格 50 次全新进程。

```
K      failed/50   bad-value histogram
2      0/50
8      2/50        512 x2
32     22/50       512 x22
128    50/50       256 x19  512 x50  768 x3
339    50/50       256 x7   512 x50  768 x15
```

✅ **已验证：在 grid 恒定不变的前提下，失败率随并发读者数单调上升，
从 0% 一路到 100%。驱动这个缺陷的是"同时在自旋并归约的 block 数"，不是 grid 大小。**

这直接否定了 V1 SUMMARY.md 里"尖锐阈值落在 grid 80 与 120 之间（80 全过、120 全错、
无中间态）"的说法：这里 K=8 → 4%、K=32 → 44%，中间态很宽，而且是概率性的。

（独立佐证：本轮用全新进程重扫 grid，得到 80 → 19/50、120 → 3/50、170 → 36/50、
340 → 50/50，**非单调**，也不是阈值形状。V1 的"阈值"来自同进程内多次重复，
掩盖了"只有 rep 0 会错"这一事实——见 SUMMARY.md。）

## 复现
```bash
./V2_g/run.sh          # N=50 per cell
```
