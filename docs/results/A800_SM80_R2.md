## 原生执行链

`scripts/a800_solve.py` 将固定模型导出、A800 target、prefill 和 seed 交给 `tilemega compile --search pipeline --selection measure`。编译器建立 ModelPlan 和 CTG，将 task ownership 与同步边界传递到 whole-program flow，随后精化候选并 replay。候选生成 typed tmexec，编译为 SM80 cubin。链接后的寄存器、共享内存和 CUDA driver 可驻留 CTA 数参与筛选与重评分。入围候选各用一个进程跑完整请求。最终产物另作完整 HF teacher-forced 与 step/loop 正确性检查，再启动独立正式计时。

SM80 和此处的 SM90 GEMM 共用 BF16 `mma.sync` 算术。SM80 用 32 个 producer lanes 发起显式地址的 16-byte `cp.async`，用 128 个消费者完成 MMA、归约与 epilogue。full/side 以 32 个 producer arrivals 发布，empty 由 128 个消费者归还。跨 stage 继续使用独立的 ring generations 和 operand banks。实际架构和实现以生成源码、链接资源和 artifact manifest 为准。

新实验按 `a800-single-v2` 记录诊断、配对、选择、正确性和正式计时。每种测试及配置只启一个独立进程。每个计时进程保留 N1/N1024 各一次 warmup 和三次计时。A/B 两臂使用同一个 allocation，顺序执行。历史有效进程及均衡顺序实验保留实际次数。CPU 编译与分析在登录节点执行。新增求解作业启动时复核提交计划中的源码、模型导出、target、prefill、seed 和 compiler 哈希。

## 已核验的变更与在途验证

| 环节 | 已有证据与选择 |
|---|---|
| SM80 fused ring 与 register stages | CPU 回归已验证同一 Qwen 几何的 2 槽和 4 槽均合法、记录键有区别、固定 4 槽不会被改写成更深值。超预算 8 槽和 Gu/Dn 不同寄存器级数被拒绝。搜索枚举合法共同深度及支持的 R1/R2/R4，只有具备对应实测 MMA key 的候选参加评分。 |
| 无静默的零代价 | additive 与 CTG flow 统一读取精确的 SM80 MMA key。Qwen B1 作业的覆盖清单显示其合法几何域中，grid108 有 38 个已有测量的唯一 key，另有 84 个缺测，grid216 有 53 个缺测。这里的计数包含 legal geometry 中的寄存器级数，尚未计入生产 body 的全部维度。 |
| Qwen B1 正常求解 | 作业 `347186` 使用已验收的 4 槽配置作 `--seed-coordinates`，按正常候选精化、链接 occupancy 和同卡端到端选择执行。已有 7.947 ms/token 继续用作对照。 |
| 共享 payload 生存期 | 隔离实现按无跨 stage 预发的坐标允许 payload 从 offset 0 复用。控制 header 和两个 operand banks 保持各自偏移，静态布局检查要求各 stage 前缀为零。存在预发时沿用交替区间及 overlap 检查。Llama-8B B1 先以同一份 theta 及 prefill 验证，再比较 TPOT、T1024 与链接资源。 |
| MoE 无效行 | 隔离的 producer 试验按物理 slot 保留五位行数，缩行时清零整个 physical TK 的新增无效区，在已领取的 down 槽发布前补 activation。另一变体仅跳过无效 accumulate stores，保留 scratch 布局、128-thread rendezvous 和 combine。两项各自以 OLMoE B1 进行正确性和配对。 |
| Llama-8B B1 现有试验 | 作业 `347018` 将 gate TN224 改为 TN256，并采用可容纳更宽 tile 的 compact scratch。两个进程的 token 完全一致，TPOT 由 11.498 升到 12.085 ms，保留原配置。作业 `347132` 的 8 条 weight copy 指令一组后由 11.466 降至 11.282 ms，SASS 显示组宽确从 4 变为 8。该结果为配对诊断，尚待 pipeline replay 与独立验收。 |
| MPK 8B B2 | 原试验重复请求的 greedy token 不一致。专门的 Ampere argmax 诊断在旧代码观察到共享内存重用冲突。隔离编译头增加行间 CTA barrier 后，正式作业 `347054` 内各次重复一致，两个首 token 匹配独立参照，TPOT 为 11.757 ms/token。本次观察只覆盖一个新的正式进程。 |

后续 P2 校准需要区分真实 producer 发射、consumer service 和重叠的 ring 工作量，并绑定生产头文件及链接资源。现有 MMA 表只提供算术阶段实测。它尚未覆盖 body 的 startup/drain、MoE 路由切换和 grid216 同时驻留的实际资源。深 ring 是否更好由新校准和端到端选择决定。P3/P4 尚无可写入本轮正式表的新结果。
