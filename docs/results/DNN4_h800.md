## Exact specification conflict

Section 3.1 fixes K=64*32=2048, BF16 (2 B), one shared A m-tile, eight distinct B n-tiles and total <8 MiB. For 128x256:

```text
A = 128 * 2048 * 2     =   524288 B = 0.5 MiB
B =   8 * 256 * 2048 * 2 = 8388608 B = 8.0 MiB
A+B                    = 8912896 B = 8.5 MiB
required A+B           < 8388608 B
```
Verified footprint for every requested tile:

| Tile | A MiB | B MiB | Total MiB | Strictly below 8 MiB |
|---|---:|---:|---:|---|
| 64x32 | 0.25 | 1 | 1.25 | True |
| 64x64 | 0.25 | 2 | 2.25 | True |
| 128x64 | 0.5 | 2 | 2.5 | True |
| 128x128 | 0.5 | 4 | 4.5 | True |
| 128x256 | 0.5 | 8 | 8.5 | False |

This is a specification contradiction, not a measured kernel failure. Sections 13/14 do not define a branch that changes K, eight B tiles or the L2 footprint bound. Section 1.2 therefore requires stopping and reporting.
Proposed minimal clarification (not applied): retain K=2048 and eight B tiles; write total <9 MiB for 128x256. No target, threshold, data count or source definition was silently changed.
Evidence: runs/dnn4/sync/phase_p_l2_footprint.json; compact decision DNN4_decisions.csv.
