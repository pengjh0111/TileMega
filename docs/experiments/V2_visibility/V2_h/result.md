# V2-h：握手载荷大小的影响

grid **固定为 170**，载荷 P ∈ {1, 4, 16, 64, 256} 个 chunk（每 chunk 1024 float）。
消费者在一个 for 循环里 reduce P 个 chunk，期望 P×1024。每格 50 次全新进程。

```
P      expect    failed/50   top bad values
1      1024      16/50       512 x16   768 x4
4      4096      24/50       1792 x24
16     16384     19/50       7936 x19  10240 x11
64     65536     16/50       59648 x8  52224 x6  59904 x4
256    262144    24/50       248832 x16  256256 x15  256512 x4
```

✅ **已验证：失败率在 32%–48% 之间基本持平，看不出随载荷单调变化的趋势。
载荷大小不是驱动变量。**

✅ **已验证：每一个错值与期望值的差都是 256 的整数倍。**

```
4096   - 1792   =  2304 =   9 x 256
16384  - 7936   =  8448 =  33 x 256
16384  - 10240  =  6144 =  24 x 256
65536  - 59648  =  5888 =  23 x 256
262144 - 248832 = 13312 =  52 x 256
262144 - 256256 =  5888 =  23 x 256
```

256 = 32 lane × 8 元素 = 恰好一个 **warp partial**。载荷越大、循环里的 reduce 次数越多，
丢掉的 partial 个数就越多，但每次都丢整数个 partial。

## 复现
```bash
./V2_h/run.sh
```
